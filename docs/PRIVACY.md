# نموذج الخصوصية والتهديد — رافد V4.3

## البيانات المحتملة

قد يستقبل رافد مقترحات غير منشورة، ملكية فكرية، ميزانيات، بيانات تعريفية للباحثين، معلومات شركاء، أو إشارات إلى مشاركين وبيانات صحية. لذلك لا يفترض النظام أن كل مشروع صالح للمعالجة أو الحفظ السحابي.

## حدود الثقة

1. **المتصفح:** يقرأ الملفات محليًا، يصنف الحساسية، ينقح المعرفات، ويعرض ما سيغادر الجهاز.
2. **Supabase Auth:** ينفذ تسجيل Google وMicrosoft وGitHub والبريد، ويحفظ جلسة متجددة في المتصفح. المفتاح المستخدم في الواجهة Publishable key عام ومقيّد بسياسات RLS؛ لا يستخدم رافد `service_role`.
3. **Supabase Database:** يحفظ الفرصة والمشاريع والقرارات المنظمة في صف خاص بالمستخدم. سياسات RLS تربط القراءة والكتابة بـ`auth.uid()`، ولا تسمح لزائر غير مسجل.
4. **خادم رافد:** يتحقق من جلسة المستخدم، يحتفظ بمفتاح النموذج في سر خادمي، يطبق حدود الاستخدام، ولا يسجل محتوى المشروع.
5. **مزود النموذج:** يستقبل النسخة المنقحة الأدنى اللازمة وفق إعداد بيانات المؤسسة.
6. **التصدير المحلي:** لا يتضمن النصوص الخام أو رمز الدخول أو مفتاح المزود؛ لكنه قد يتضمن معلومات منظمة حساسة، ولذلك يبقى تحت مسؤولية المستخدم.

عند اختيار Ollama المحلي تبقى مدخلات التحليل داخل الجهاز: المتصفح → خادم رافد المحلي → Ollama المحلي. أما تسجيل الحساب والحفظ في Supabase فهما سحابيان إذا ظلا مفعّلين.

عند اختيار Groq مع ZDR يمر المحتوى المنقح عبر Groq أثناء الاستدلال، لكن إعداد ZDR يمنع الاحتفاظ بمحتوى الطلب والاستجابة. تبقى بيانات استخدام وصفية وفق سياسة المزود. هذا مسار سحابي خصوصي، وليس معالجة محلية.

## ما يُحفظ وما لا يُحفظ

| العنصر | المكان | السلوك الافتراضي |
|---|---|---|
| جلسة الدخول ورمز التجديد | تخزين المتصفح الذي تديره Supabase | تبقى وتتجدد حتى الخروج أو الإلغاء أو مسح بيانات المتصفح |
| الفرصة والمشاريع والنتائج المنظمة | `rafid_workspaces` في Supabase | صف واحد خاص بالمستخدم ومحمي بـRLS |
| النص الخام للملفات والفرصة | ذاكرة الصفحة أثناء العملية | يُمسح من حقول العمل بعد الاستخراج ولا يدخل لقطة مساحة العمل |
| مفتاح Groq/OpenAI | Secret/Environment في الخادم | لا يعود إلى المتصفح أو المستخدم |
| Publishable key الخاص بـSupabase | الإعداد العام والمتصفح | قيمة عامة مقصودة، وأمان البيانات يعتمد على RLS |
| `service_role` | لا يستخدمه رافد | يجب ألا يوضع في الواجهة أو الحزمة أو إعداداتها |

قد تتضمن النتائج المنظمة أسماء أو حقائق بقيت بعد التنقيح؛ عدم حفظ النص الخام لا يعني أن كل نتيجة مجهولة الهوية. راجع التصنيف والمخرجات قبل تفعيل الحفظ السحابي لبيانات حقيقية.

## تهديدات ودفاعات

| التهديد | الدفاع الحالي | ما يلزم للإنتاج |
|---|---|---|
| تسرب مفتاح المزود | سر خادمي، لا يوجد في الواجهة أو الإعداد العام، ورسائل الخطأ تنقح أنماط المفاتيح | Secret manager/Key Vault ودوران مفاتيح ومراقبة استخدام |
| وصول مستخدم إلى مساحة غيره | RLS مفعل ومفروض، والسياسات تقارن `auth.uid()` مع `user_id` | اختبارات اختراق دورية وسجل تدقيق وتنبيهات |
| سرقة جلسة متصفح | HTTPS، تجديد رموز، وخروج صريح | MFA، مدة جلسة مؤسسية، حماية أجهزة وسياسة جلسة واحدة عند الحاجة |
| نشر واجهة وخادم على أصلين مع CORS خاطئ | قائمة Origins وضبط `Authorization` في CORS | أصل واحد مفضل، وقائمة نطاق دقيقة بلا `*` في الإنتاج |
| استنزاف المفتاح المشترك | حد لكل مستخدم وحد يومي عام | مخزن حدود موزع وميزانية/تنبيهات عند تعدد مثيلات الخادم |
| ادعاء ZDR خطأً | وضع `strict_zdr` يرفض الاتصال دون تأكيد صريح | تحقق تعاقدي مركزي ومراجعة إعداد المزود دوريًا |
| جلب رابط داخلي ضار SSRF | HTTPS فقط، فحص DNS، منع الشبكات الخاصة والتحويلات | وكيل خروج وقائمة نطاقات مؤسسية |
| إرسال ملف مقيّد | منع في الواجهة والخادم؛ والحفظ السحابي للمقيّد محظور | DLP مؤسسي وسياسات منع خروج |
| حفظ محتوى سري في Supabase | الحفظ السحابي للسري متوقف افتراضيًا | اعتماد أمني وتعاقدي وتشفير/موقع بيانات مناسب قبل السماح |
| ظهور PII في النص أو النتيجة | تنقيح محلي ومعاينة بشرية | كاشف PII مؤسسي واختبارات عربية ولهجات |
| Prompt injection داخل الملفات | تعليمات النظام تعامل الملف كبيانات غير موثوقة | اختبارات خصومة ومراقبة انحراف |
| تسرب المحتوى في السجلات | السجلات تحتوي معرف طلب وحجومًا وحالات، لا النصوص | مراجعة منصة السجلات وسياسة احتفاظ |
| قرار آلي خاطئ | بوابات حتمية ومراجعة بشرية إلزامية | معايرة دورية وقياس أخطاء الأهلية |
| سلسلة إمداد الواجهة | أصول PDF/DOCX/Supabase محلية ضمن الحزمة | فحص اعتماديات وتحديثات أمنية منتظمة |

## قواعد التشغيل

- لا تستخدم بيانات مقيّدة مع API خارجي أو حفظ سحابي.
- لا تُدخل بيانات مشاركين أو سجلات صحية خام في التجربة.
- الحفظ السحابي للمحتوى السري متوقف افتراضيًا عبر `RAFID_ALLOW_CONFIDENTIAL_CLOUD_PERSISTENCE=false`.
- المحتوى السري يحتاج ZDR مؤكدًا أو معالجة داخلية معتمدة بعد التنقيح، ولا يكفي أن يكون `store:false`.
- لا تجعل `GROQ_ZERO_DATA_RETENTION_CONFIRMED=true` إلا بعد تفعيل ZDR فعليًا في Groq Data Controls.
- لا تستخدم `RAFID_ALLOWED_ORIGINS=*` في الإنتاج عند فصل الواجهة عن الخادم.
- لا تضع `.env` في GitHub، ولا ترسل مفاتيح المزود في محادثة أو بريد.
- على الأجهزة العامة سجل الخروج ولا تعتمد على بقاء الجلسة.
- محدد المعدل الحالي داخل ذاكرة مثيل الخادم؛ استخدم مخزنًا موزعًا/API Gateway عند التوسع الأفقي.
