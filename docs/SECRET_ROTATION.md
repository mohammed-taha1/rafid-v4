# خطوات تدوير أسرار رافد

## 1. قبل التدوير

1. احصر البيئات التي تستخدم المفتاح: محلي، staging، إنتاج، GitHub، Render، Azure، وSupabase.
2. حدد مالك المفتاح والخدمات التي ستتوقف عند تغييره.
3. افتح مدير أسرار الاستضافة ومدير كلمات المرور المعتمد، ولا تضع المفتاح الجديد في ملف أو رسالة أو تذكرة.
4. جهز اختبار صحة لا يطبع الترويسات أو متغيرات البيئة.

## 2. رمز GitHub الشخصي

1. افتح إعدادات المطور في حساب GitHub المالك.
2. ألغِ الرمز القديم فورًا.
3. أنشئ رمزًا جديدًا بأقل صلاحيات وأقصر مدة لازمة.
4. خزنه في مدير الأسرار المعتمد فقط.
5. حدّث الأدوات أو الاستضافة التي تحتاجه، ثم أعد تسجيل الدخول عند الحاجة.
6. تحقق من الوصول إلى المستودع دون طباعة الرمز.
7. راجع سجل استخدام الرمز والتنبيهات الأمنية بعد الإلغاء.

## 3. مفتاح Groq

1. أنشئ مفتاحًا جديدًا من حساب Groq الصحيح.
2. حدّث `GROQ_API_KEY` في مدير أسرار staging أولًا.
3. أعد تشغيل الخدمة واختبر تحليلًا منقحًا غير حساس.
4. حدّث سر الإنتاج وأعد تشغيل النسخ العاملة.
5. ألغِ المفتاح القديم بعد نجاح الاختبار.
6. راجع الحصة وسجل الاستخدام لأي نشاط غير متوقع.
7. تحقق من إعداد Zero Data Retention قبل ضبط تأكيده في البيئة.

## 4. مفتاح Supabase العام

1. أنشئ أو دوّر المفتاح العام من إعدادات مشروع Supabase.
2. حدّث `SUPABASE_ANON_KEY` في مدير أسرار الخادم.
3. أعد تشغيل الخدمة واختبر تسجيل الدخول وتجديد الجلسة والخروج.
4. اختبر RLS بحسابين مستقلين قبل إلغاء المفتاح السابق.
5. تحقق أن الواجهة تستقبل المفتاح العام فقط عبر `/api/rafid/public/config`.

## 5. مفتاح Supabase عالي الصلاحية

1. أوقف أي استخدام غير ضروري لـ`SUPABASE_SERVICE_ROLE_KEY`.
2. إذا كان مستخدمًا خارج رافد، أنشئ بديلًا من لوحة Supabase وحدّث الخدمة الخادمية المعنية فقط.
3. اختبر المهمة الخادمية المعنية دون إرسال المفتاح إلى المتصفح.
4. ألغِ المفتاح السابق بعد التحقق.
5. راجع سجلات قاعدة البيانات وسياسات RLS ونطاق العمليات المنفذة به.
6. اترك المتغير غير مضبوط في رافد ما دام التطبيق لا يحتاجه.

## 6. مفاتيح OpenAI أو Azure OpenAI الاختيارية

1. أنشئ مفتاحًا جديدًا في حساب المزود الصحيح.
2. حدّث متغيرات المزود في مدير أسرار staging.
3. اختبر المصادقة والنموذج والنشر وسياسة الاحتفاظ.
4. حدّث الإنتاج ثم أعد تشغيل الخدمة.
5. ألغِ المفتاح القديم وراجع الاستخدام والحصة.

## 7. بعد كل تدوير

1. شغّل فحص الأسرار على النسخة الحالية وتاريخ Git دون طباعة القيم.
2. شغّل typecheck وlint والاختبارات والبناء.
3. اختبر الصفحة العامة دون Supabase، ثم اختبر المصادقة والتحليل في staging.
4. تحقق أن السجلات ورسائل الخطأ لا تحتوي قيم متغيرات البيئة.
5. سجل تاريخ التدوير والمالك ونطاق الخدمة في سجل أمني خاص، دون تسجيل المفتاح.
6. إذا ظهر سر حقيقي في تاريخ Git، ألغِه أولًا ثم خطط لتنظيف التاريخ بالتنسيق مع جميع المساهمين؛ لا تعِد كتابة التاريخ تلقائيًا.
