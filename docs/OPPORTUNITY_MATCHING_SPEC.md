# تحليل ملاءمة البحث لفرصة تمويل محددة

آخر تحديث: 9 أغسطس 2026

## الهدف

ينقل هذا المسار رافد من تقييم جاهزية عام إلى إجابة موثقة عن سؤال محدد: هل البحث أو المشروع ملائم ومؤهل لفرصة التمويل المدخلة، وما الذي يجب إغلاقه قبل التقديم؟

## رحلة المستخدم

1. يدخل المستخدم نص فرصة التمويل أو يرفع PDF أو DOCX أو TXT.
2. يمكنه إضافة اسم الفرصة والجهة والرابط الرسمي وموعد الإغلاق كبيانات مساعدة.
3. يدخل البحث أو المشروع كنص أو ملف، دون اسم الباحث أو بيانات شخصية.
4. يؤكد معالجة المدخلين لهذا الطلب فقط.
5. يستخرج رافد شروط الفرصة، ثم حقائق البحث، ثم يجري المطابقة.
6. تظهر الأهلية قبل درجة الملاءمة، مع الأدلة والفجوات وخطة الإغلاق وحزمة التقديم.

يبقى مسار التقييم العام متاحًا بصورة مستقلة لمن لم يختر فرصة بعد.

## تدفق التنفيذ

```text
نص/ملف الفرصة
  → POST /api/rafid/opportunity/extract
  → OpportunityProfile

نص/ملف البحث
  → POST /api/rafid/extract
  → ProjectData

OpportunityProfile + ProjectData
  → POST /api/rafid/opportunity/assess
  → rafid.opportunity-match.v1
```

لا يعيد أي مسار النص الخام ضمن النتيجة، ولا يخزنه الخادم افتراضيًا.

## قواعد القرار

- شروط الفرصة المدخلة هي مصدر الحقيقة الوحيد للأهلية.
- الشرط الإلزامي الصارم يظهر كبوابة مستقلة.
- غياب الدليل يعني «غير معروف»، وليس «مستوفى» أو «غير مستوفى».
- التعارض الصريح فقط يسمح بحالة «غير مستوفى».
- لا تتغلب الدرجة على بوابة أهلية فاشلة.
- البحث الناقص يظل مدخلًا صالحًا، وتظهر معلوماته الغائبة كفجوات بدل تعطيل الرحلة.
- كل حكم يميز اقتباس الفرصة عن دليل البحث.
- القرار النهائي للجهة الممولة والمراجع البشري.

## حالات الأهلية

- `مؤهل`: جميع البوابات الصارمة مستوفاة وفق الأدلة المتاحة، ولا توجد فجوة مانعة مفتوحة.
- `مؤهل بشروط`: يمكن إغلاق شروط أو أدلة محددة قبل التقديم.
- `غير محسوم`: لا يوجد دليل كافٍ لحسم شرط صارم.
- `غير مؤهل`: يوجد تعارض صريح مع شرط صارم غير قابل للإصلاح في الدورة الحالية.

## نتيجة المستخدم

- هوية الفرصة والجهة والموعد عند توفرها.
- حالة الأهلية وسببها.
- توصية مراجعة بشرية.
- درجة الملاءمة والجاهزية من 100.
- قوة الأدلة من 100.
- ثقة التحليل من 100.
- جميع الشروط الصارمة مع اقتباس الفرصة وأدلة البحث.
- أبعاد الملاءمة المفسرة.
- الفجوات المانعة والحرجة والمهمة والتحسينية.
- خطة إغلاق مرتبة تتضمن السبب والمخرج والمالك الوظيفي.
- حالة وثائق حزمة التقديم.
- أسئلة للفريق وأسئلة للجهة الممولة.
- تنبيه ثابت لا يمكن للنموذج إزالته.

## الخصوصية والأمان

- لا يطلب المسار اسم الباحث أو بريده أو هاتفه.
- لا يُقبل الرابط إلا كمرجع HTTPS؛ لا يعتمد المسار الجديد على جلبه تلقائيًا.
- يقرأ الملف في الذاكرة باستخدام طبقة الإدخال الآمنة الحالية.
- لا يحفظ النص أو الملف أو النتيجة افتراضيًا.
- يظل مفتاح Groq في الخادم فقط، ويطبق إعداد `strict_zdr` في بيئة الإنتاج.
- يعامل النصان كبيانات غير موثوقة، ولا ينفذ تعليمات مضمّنة داخلهما.
- يمنع الضغط المكرر، ويدعم إلغاء الطلب الحالي.

## معايير القبول

- يستطيع المستخدم الاختيار بوضوح بين التقييم العام والمطابقة لفرصة.
- يقبل كل مدخل نصًا أو ملفًا واحدًا، لا الاثنين معًا.
- يرفض نص فرصة أقصر من 100 حرف وبحثًا أقصر من 30 حرفًا.
- لا يبدأ الإرسال دون موافقة المعالجة المؤقتة.
- تظهر مراحل حقيقية بلا نسبة تقدم زائفة.
- تظهر حالة الأهلية قبل الدرجة.
- لا يعرض JSON أو اسم النموذج أو أسرار الخادم.
- يظهر «غير معروف» عند غياب الدليل.
- يمكن نسخ الخلاصة وطباعة التقرير وبدء تحليل جديد.
- يعمل التصميم RTL على 390px وعلى الشاشة الكبيرة.
- تنجح فحوص الصياغة والأنواع والاختبارات والبناء.

## خارج نطاق هذه المرحلة

- البحث الحي أو الآلي عن فرص على الإنترنت.
- قاعدة فرص مركزية.
- اقتراح عدة فرص وترتيبها.
- حسابات المؤسسات والمحافظ البحثية.
- بوابة الجهات الممولة.
- اتخاذ قرار قبول أو رفض آلي.
