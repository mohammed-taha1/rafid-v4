# انتقال واجهة رافد إلى Cloudflare

## القرار

تنقل الواجهة الثابتة أولًا إلى Cloudflare Workers Static Assets، بينما يبقى خادم التحليل الحالي على Render في مرحلة التحقق. يعمل Cloudflare كواجهة ونقطة دخول من أصل واحد، ويوجّه `/api/rafid/*` و`/health` إلى Render. لا تنتقل مفاتيح Groq أو Supabase الخادمة إلى Cloudflare، ولا تتغير طريقة معالجة البحث في هذه المرحلة.

يبقى `https://rafid-v4.onrender.com` عاملًا دون تحويل إجباري حتى يستمر QR القديم. بعد تثبيت نطاق مملوك لرافد يضاف الرابط الجديد إلى QR والمواد الجديدة، ويظل الرابط القديم بوابة توافق أو يعيد التوجيه لاحقًا بعد فترة معلنة.

يشغّل `npm run performance` قياس الاستخراج المحلي. وعند ضبط `RAFID_PERF_URL` يقيس أيضًا الواجهة و`/health`. يشغّل `npm run test:live` رحلة المزود المعتمدة على بيانات التدريب فقط.

## بنية النشر

- `wrangler.jsonc`: مصدر إعداد Cloudflare؛ ينشر مجلد `frontend` كأصول ثابتة.
- `cloudflare/worker.mjs`: يمرر فقط `/api/rafid/*` و`/health` إلى `RAFID_API_ORIGIN`، ويرفض الطرق غير المسموحة ولا يخزن الاستجابات.
- `frontend/_headers`: رؤوس الأمان وسياسة التخزين المؤقت. لا تُخزّن صفحة البداية أو استجابات API.
- `RAFID_API_ORIGIN`: إعداد عام غير سري، وقيمته الانتقالية `https://rafid-v4.onrender.com`.

## خطوات الإطلاق

1. أنشئ Worker باسم `rafid` من المستودع أو نفّذ `npm run deploy:cloudflare` بعد تسجيل الدخول.
2. تحقق من الصفحة الثابتة ثم `/health` ثم `/api/rafid/public/config` عبر نطاق Cloudflare.
3. اختبر رحلة تحليل تدريبية كاملة من النطاق الجديد وتحقق من استمرار `provider=groq` وعدم استخدام fallback.
4. أضف نطاق Cloudflare النهائي إلى قائمة Redirect URLs في Supabase بصيغة `https://<domain>/**` قبل اختبار دخول المؤسسات.
5. ثبّت نطاقًا مملوكًا لرافد، ثم أضفه إلى Redirect URLs وإلى `APP_URL`/القائمة المسموحة في إعدادات الإنتاج عند الحاجة.
6. لا توقف Render ولا تغير الرابط القديم قبل مرور اختبار QR ورحلة التحليل والدخول على النطاقين.

## بوابات الانتقال اللاحقة للخادم

لا ينقل تنفيذ التحليل إلى Cloudflare قبل نجاح ما يلي:

- استعادة Job بعد إعادة تشغيل العامل، بدل الاعتماد على `Map` داخل ذاكرة عملية واحدة.
- قرار موثق بشأن تشفير الحالة ومدة الاحتفاظ وموافقة المستخدم؛ لا يحفظ نص البحث افتراضيًا.
- اختبار PDF وDOCX عند حدود الحجم والذاكرة.
- اختبار إلغاء الطلب، المهلة، إعادة المحاولة، وعدم تكرار إرسال البحث.
- تحقق ZDR مستقل للمزود المختار، مع عدم اعتبار `لا يستخدم للتدريب` مساويًا لـZDR.

## التراجع

لا يتأثر رابط Render القديم بهذا الانتقال. عند فشل واجهة Cloudflare، أزل ربط النطاق الجديد أو أعده إلى آخر نشر ناجح من Cloudflare، واستعمل رابط Render مباشرة. لا يتطلب التراجع نقل بيانات بحث لأن الواجهة لا تحفظ محتوى الأبحاث.

## تحقق الحزمة قبل النشر

- نجح تشغيل Worker محليًا عبر Wrangler، وحُمّلت الصفحة الرئيسية بحالة `200` من الأصول الثابتة.
- نجح تمرير `/health` إلى Render بحالة `200` وسياسة `no-store`، وبقي المحتوى العام منفصلًا عن الخادم.
- نجحت ترويسات CSP ومنع تضمين الصفحة وتقييد الاتصال بـSupabase والأصل نفسه.
- يزيل الـWorker أي `X-Forwarded-For` يرسله العميل ويستبدله بعنوان Cloudflare الموثوق قبل تمريره، لحماية دقة تحديد المعدل.
- نجح بناء Cloudflare بوضع `dry-run` مع 32 أصلًا ثابتًا. لم يحدث نشر خارجي أو ربط نطاق حتى الآن.
