# مختبر جودة رافد

## الهدف

مختبر الجودة هو بوابة إصدار لمحرك المطابقة، وليس عرضًا تجميليًا. يشغّل `npm run quality` مجموعة ثابتة من 48 حالة، ويوقف الفحص إذا انخفض أي مقياس عن الحد الأدنى أو عن خط الأساس المحفوظ.

## التغطية الحالية

- أبحاث مكتملة وناقصة وضعيفة الأدلة.
- أهلية مكتملة، مشروطة، غير محسومة، وغير مستوفاة بمانع صريح.
- العربية والإنجليزية.
- المياه والصحة والطاقة والتعليم.
- ملفات ممثلة بصيغ PDF وDOCX وTXT.
- تعارضات داخلية، ومستندات طويلة ضعيفة الاستخراج.
- ثلاث إعادات لكل حالة لقياس الثبات؛ أي اختلاف حتمي يفشل البوابة.

النسخة الحالية معيار تركيبي منظم ومراجع داخل المستودع. لا تعني نتيجته أن دقة النموذج الحي 100%. قبل اعتماد قرار مؤسسي واسع يجب إضافة حالات واقعية منزوعة الهوية يراجعها خبيران على الأقل، دون حفظ نصوص الأبحاث الحساسة في Git.

## المقاييس وحدود الإصدار

| المقياس | الحد الأدنى | المعنى |
|---|---:|---|
| دقة بوابات الأهلية | 95% | تطابق حالة الأهلية مع مرجع الحالة |
| صحة مواضع الأدلة | 90% | وجود الصفحة أو القسم المتوقع في سجل الأدلة |
| السلامة من الاختلاق | 100% | عدم ظهور ادعاءات محظورة غير موجودة |
| استرجاع المعلومات المفقودة | 90% | ظهور النقص المتوقع في البوابات أو الفجوات |
| ثبات الإعادة | 100% | تطابق البصمة الحتمية عبر ثلاث إعادات |
| التوافق مع المرجع البشري | 85% | وقوع القرار أو نطاق الدرجة ضمن مرجع الحالة |
| فائدة خطة العمل | 85% | وجود إجراء وسبب ومخرج وربط بالفجوة |
| اكتشاف التناقضات | 90% | اكتشاف العدد الأدنى المحدد في مرجع الحالة |

## بوابة عدم التراجع

- `benchmarks/quality-baseline.json` هو خط الأساس المقبول.
- `scripts/quality-lab-test.js` يقارن النتيجة الجديدة بالحدود وبخط الأساس.
- فشل أي مقياس يجعل `npm test` وGitHub Actions يفشلان.
- لا يحدّث خط الأساس لمجرد تمرير تغيير؛ يلزم تفسير المقياس، ومراجعة الحالات المتأثرة، واعتماد بشري موثق.

## بنية الحالة

كل حالة تحمل نوع المصدر واللغة والتخصص ومدخلات الفرصة والمشروع وحكم المزود، ثم مرجعًا يتضمن الأهلية، مواضع الأدلة، الادعاءات المحظورة، النواقص، التناقضات، نطاق الدرجة، وكلمات خطة العمل. لا تحتوي الحالات على مفاتيح API أو بيانات مستخدمين.

## تشغيل المختبر

```powershell
npm.cmd run quality
```

ثم شغّل بوابة المشروع كاملة:

```powershell
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
```

## إضافة حالات واقعية لاحقًا

1. انزع الهوية وأي بيانات حساسة قبل إدخال الحالة.
2. اجعل خبيرين يحددان البوابات والأدلة والنواقص والتناقضات مستقلين.
3. احسم الاختلافات وسجل مرجعًا ذهبيًا دون نص البحث الكامل إن أمكن.
4. أضف الحالة إلى مجموعة خاصة غير عامة إذا تعذر إخفاء الهوية بأمان.
5. شغّل المختبر على الإصدار الحالي والمرشح، ولا تعتمد المرشح إذا خفّض مقياسًا.
