# قائمة تحقق إطلاق رافد MVP

## إدارة المصدر

- [x] العمل على فرع إطلاق منفصل عن `main`.
- [x] إنشاء سجل تقدم وقرارات ومشكلات مفتوحة.
- [x] عدم تغيير منطق التطبيق في مرحلة التهيئة.
- [x] توسيع `.gitignore` للأسرار ومخرجات البناء والملفات المؤقتة.
- [ ] حماية `main` واشتراط مراجعة وفحوص ناجحة قبل الدمج.
- [ ] مراجعة الفرق النهائي والتأكد من خلوه من الأسرار والبيانات الشخصية.

## البناء والجودة

- [ ] تنفيذ `npm ci` في بيئة نظيفة مدعومة.
- [ ] نجاح `npm run check`.
- [ ] نجاح `npm test`.
- [ ] نجاح `npm audit --omit=dev` أو توثيق الاستثناءات المقبولة.
- [ ] إضافة CI يعمل على pull requests وعلى فرع الإطلاق.
- [ ] تنفيذ smoke test للحاوية المبنية من `Dockerfile`.

## الأسرار والإعدادات

- [ ] حفظ مفاتيح Groq/OpenAI/Azure وSupabase في مدير أسرار الاستضافة فقط.
- [ ] التأكد من عدم وجود `.env` أو `.env.local` أو مفاتيح أو شهادات في Git.
- [ ] ضبط `RAFID_DEPLOYMENT_MODE=shared` و`RAFID_PROVIDER_CONFIGURATION_MODE=server` للإنتاج.
- [ ] تفعيل `RAFID_AUTH_REQUIRED=true`.
- [ ] ضبط `RAFID_ALLOWED_ORIGINS` على النطاقات الفعلية فقط ومنع `*` في الإنتاج.
- [ ] تأكيد ZDR فعليًا قبل تفعيل أي علامة تؤكد اعتماده.

## Supabase والمصادقة

- [ ] تطبيق `supabase/rafid_schema.sql` في مشروع staging.
- [ ] اختبار RLS حيًا بحسابين مستقلين والتحقق من العزل.
- [ ] اختبار Google وMicrosoft وGitHub وMagic Link حسب المزودين المفعّلين.
- [ ] مراجعة Site URL وRedirect URLs للإنتاج وstaging وlocalhost.
- [ ] اختبار تسجيل الخروج وإلغاء الجلسة وتجديد الرمز.

## الخصوصية والأمان

- [ ] اختبار منع المحتوى المقيّد من أي API خارجي.
- [ ] اختبار التنقيح والمعاينة والموافقة على عينة واقعية منزوعة الهوية.
- [ ] التحقق أن الواجهة والاستجابات والسجلات لا تعرض مفاتيح أو `service_role`.
- [ ] إعادة اختبار SSRF وحدود حجم الطلب وCORS وترويسة Authorization.
- [ ] تحديد مدة السجلات وسياسة الوصول والحذف.

## التشغيل والنشر

- [ ] نشر staging على HTTPS بأصل واحد للواجهة والخادم إن أمكن.
- [ ] نجاح `/api/rafid/health` و`/api/rafid/public/config` دون كشف بيانات حساسة.
- [ ] ضبط مراقبة الأخطاء والزمن والحصة اليومية والتنبيهات.
- [ ] اعتماد مخزن موزع للحدود عند التشغيل بأكثر من مثيل.
- [ ] إعداد rollback موثق واختباره.
- [ ] توثيق مسؤول التشغيل وقنوات التصعيد.

## تجربة MVP وقرار الإطلاق

- [ ] اختيار جهة واحدة وفرصة تمويل حية واحدة.
- [ ] تجهيز 5–10 مشاريع حقيقية بموافقات مناسبة.
- [ ] تعيين مراجعَين ومعيار اتفاق واضح.
- [ ] قياس خط الأساس اليدوي لزمن القرار.
- [ ] قياس زمن رافد واتفاق المراجعين والفجوات المغلقة والتقديم قبل الموعد.
- [ ] تسجيل العيوب والملاحظات دون حفظ نصوص خام أو أسرار.
- [ ] عقد مراجعة go/no-go موثقة قبل الإطلاق العام.
