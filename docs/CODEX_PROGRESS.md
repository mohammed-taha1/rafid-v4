# تقدم إطلاق رافد MVP

آخر تحديث: 25 يوليو 2026

## وصف مختصر للمشروع

رافد V4.3 منصة عربية تركز على جاهزية المشروع لفرصة تمويل محددة. تستخرج شروط الفرصة، تتحقق من الأهلية والأدلة، وتنتج سجل فجوات وخطة إغلاق وحزمة قرار مؤسسي. المنصة لا تعد بالتمويل ولا تستبدل المراجعة البشرية.

## التقنية الحالية بعد الاكتشاف

- Node.js 20.16 أو 22 مع CommonJS.
- خادم Node موحد، مع دعم نشر بديل عبر Azure Functions v4.
- واجهة HTML وJavaScript تُخدَّم من `frontend/` مع أصول PDF وDOCX محلية.
- OpenAI SDK لمسارات OpenAI وAzure OpenAI وGroq، ودعم Ollama محليًا.
- Supabase Auth وPostgres وRow Level Security للحسابات ومساحات العمل.
- Docker على أساس `node:22-bookworm-slim` للتشغيل الإنتاجي.
- اختبارات Node مخصصة وفحوص JavaScript وتدقيق واجهة ثابت واختبار خادم smoke.

## حالة البناء والاختبارات

- أوامر المشروع المعرفة: `npm run check` و`npm test`.
- يذكر `VERIFICATION.md` بتاريخ 18 يوليو 2026 أن الفحوص الآلية والتثبيت النظيف و`npm audit --omit=dev` نجحت وقتها.
- لم تُشغّل الاختبارات في هذه المرحلة لأن العمل تم عبر GitHub دون checkout محلي أو تعديل لمنطق التطبيق.
- لا توجد حالات CI مسجلة على آخر commit في `main`، كما أن تقرير التحقق أقدم من آخر commit بتاريخ 23 يوليو 2026؛ لذلك يجب إعادة الفحوص على الفرع قبل اعتباره جاهزًا للإطلاق.

## المراحل المخطط لها

1. **المرحلة 0 — خط أساس آمن:** فرع إطلاق منفصل، ملفات متابعة، وقواعد تجاهل محسنة.
2. **المرحلة 1 — تحقق قابل للتكرار:** تثبيت نظيف وتشغيل check/test/audit وإضافة CI.
3. **المرحلة 2 — جاهزية الإعدادات والأسرار:** مراجعة بيئات Supabase والمزود وCORS وZDR دون تخزين أسرار في Git.
4. **المرحلة 3 — بيئة staging:** نشر HTTPS واحد للواجهة والخادم، ثم اختبارات الصحة والمصادقة والحفظ وRLS.
5. **المرحلة 4 — تجربة MVP:** فرصة تمويل حية و5–10 مشاريع ومراجعان وقياس الزمن والاتفاق وإغلاق الفجوات.
6. **المرحلة 5 — قرار الإطلاق:** مراجعة المخاطر والمراقبة وحدود الاستخدام وخطة الاسترجاع ثم قرار go/no-go.

## الملفات المهمة

- `README.md` و`START_HERE_AR.md`: تعريف المنتج والتشغيل.
- `package.json` و`package-lock.json`: الإصدارات وأوامر البناء والاختبار.
- `src/index.js` و`src/lib/`: الخادم ومنطق الخصوصية والذكاء الاصطناعي والتقييم.
- `frontend/index.html` و`frontend/rafid-v4.js`: نقطة دخول الواجهة ومنطقها.
- `scripts/run-rafid.js`: تشغيل الواجهة والخادم على أصل واحد.
- `tests.js` و`scripts/*-test.js`: مجموعة التحقق الآلي.
- `Dockerfile`: صورة التشغيل الإنتاجية.
- `supabase/rafid_schema.sql`: مخطط مساحة العمل وسياسات RLS.
- `.env.example`: أسماء إعدادات البيئة دون قيم تشغيلية.
- `VERIFICATION.md` و`docs/PILOT.md`: دليل التحقق وبروتوكول التجربة.

## القرارات الهندسية

- إبقاء مفتاح المزود سرًا خادميًا وعدم إرساله إلى المتصفح.
- فرض التحقق من جلسة Supabase قبل الطلبات المحمية.
- استخدام RLS لعزل مساحة كل مستخدم.
- منع المعالجة الخارجية للمحتوى المقيّد، واعتماد `strict_zdr` افتراضيًا للسحابة.
- عدم مساواة `store:false` مع Zero Data Retention.
- إبقاء قرار الأهلية حتميًا؛ لا تتغلب الدرجة على فشل بوابة إلزامية.
- تفضيل أصل HTTPS واحد للواجهة والخادم لتقليل أخطاء CORS وتسرب الإعدادات.
- عدم تغيير منطق التطبيق ضمن المرحلة 0.

## المشكلات المفتوحة

- لا يوجد دليل CI حديث مرتبط بآخر commit.
- يلزم اختبار حي لـOAuth وSupabase RLS وGroq/ZDR باستخدام حسابات المالك.
- محدد المعدل والحد اليومي محفوظان في ذاكرة كل مثيل؛ التوسع المتعدد يحتاج مخزنًا موزعًا.
- يجب تثبيت نطاق الإنتاج وقائمة `RAFID_ALLOWED_ORIGINS` وخطة إدارة الأسرار.
- يجب قياس حدود الحصة المجانية للمزود تحت حمل تجربة حقيقية.
- يلزم تعريف مراقبة تشغيلية وتنبيهات وخطة rollback قبل الإطلاق العام.

## آخر مرحلة مكتملة
